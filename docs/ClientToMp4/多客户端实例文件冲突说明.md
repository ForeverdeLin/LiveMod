# 多客户端实例文件冲突说明

## 一、关键概念

### 1.1 单例模式的作用范围

**重要：单例模式只在单个进程内有效！**

- **单进程内**：单例模式确保只有一个实例
- **多进程间**：每个进程都有自己独立的单例实例

```
进程1 (ClientToMp4)         进程2 (ClientToMp4)
    ↓                            ↓
单例实例1 (m_pInstance1)    单例实例2 (m_pInstance2)
    ↓                            ↓
文件1.mp4                    文件2.mp4
```

### 1.2 文件路径设置

**TCP模式：**
```cpp
// CCVideoClient.cpp:117
CCVideoWriter::GetInstance()->StartVideoWriterWithPath("./20211115.mp4");
```
- **硬编码文件名**：`./20211115.mp4`
- **所有TCP客户端实例都会写入同一个文件**

**RTMP模式：**
```cpp
// main.cpp:132-134
snprintf(filename, sizeof(filename), "record_%04d%02d%02d_%02d%02d%02d.mp4",
         t->tm_year + 1900, t->tm_mon + 1, t->tm_mday,
         t->tm_hour, t->tm_min, t->tm_sec);
CCVideoWriter::GetInstance()->StartVideoWriterWithPath(filename);
```
- **动态文件名**：`record_YYYYMMDD_HHMMSS.mp4`
- **基于启动时间的秒级精度**

## 二、多客户端实例场景分析

### 2.1 场景1：多个TCP模式客户端

**启动命令：**
```bash
# 终端1
./ClientToMp4 tcp 192.168.1.100 30000

# 终端2
./ClientToMp4 tcp 192.168.1.100 30000
```

**结果：**
- ❌ **文件冲突**：两个进程都写入 `./20211115.mp4`
- ❌ **文件损坏**：多个进程同时写入同一个文件会导致：
  - 文件头被覆盖
  - 数据交错写入
  - 文件结构损坏
  - 无法正常播放

**原因：**
- TCP模式使用硬编码文件名
- 没有进程ID或时间戳区分
- 多个进程打开同一个文件进行写入

### 2.2 场景2：多个RTMP模式客户端（不同时间启动）

**启动命令：**
```bash
# 终端1（10:30:15启动）
./ClientToMp4 rtmp rtmp://server1/stream1

# 终端2（10:30:20启动）
./ClientToMp4 rtmp rtmp://server2/stream2
```

**结果：**
- ✅ **文件不冲突**：生成不同的文件名
  - 进程1：`record_20241115_103015.mp4`
  - 进程2：`record_20241115_103020.mp4`

**原因：**
- RTMP模式使用动态文件名（包含时间戳）
- 启动时间不同，文件名不同

### 2.3 场景3：多个RTMP模式客户端（同一秒启动）

**启动命令：**
```bash
# 终端1（10:30:15启动）
./ClientToMp4 rtmp rtmp://server1/stream1

# 终端2（10:30:15启动，同一秒）
./ClientToMp4 rtmp rtmp://server2/stream2
```

**结果：**
- ❌ **文件冲突**：两个进程都生成 `record_20241115_103015.mp4`
- ❌ **文件损坏**：同时写入同一个文件

**原因：**
- 文件名只精确到秒级
- 同一秒内启动的多个进程会生成相同文件名

### 2.4 场景4：TCP模式和RTMP模式同时运行

**启动命令：**
```bash
# 终端1（TCP模式）
./ClientToMp4 tcp 192.168.1.100 30000

# 终端2（RTMP模式）
./ClientToMp4 rtmp rtmp://server/stream
```

**结果：**
- ✅ **文件不冲突**：写入不同的文件
  - TCP模式：`./20211115.mp4`
  - RTMP模式：`record_20241115_103015.mp4`

**原因：**
- 文件名不同，不会冲突

## 三、文件冲突的影响

### 3.1 文件损坏机制

当多个进程同时写入同一个文件时：

1. **文件头覆盖**
   - 每个进程都会调用 `avformat_write_header()` 写入文件头
   - 后启动的进程会覆盖先启动进程的文件头
   - 导致文件结构损坏

2. **数据交错写入**
   - 多个进程的 `av_interleaved_write_frame()` 调用会交错执行
   - 视频帧和音频帧可能写入错误位置
   - 时间戳混乱

3. **文件尾不完整**
   - 每个进程退出时都会调用 `av_write_trailer()`
   - 后退出的进程会覆盖文件尾
   - 导致文件无法正常播放

### 3.2 实际表现

- **文件大小异常**：可能很大（多个进程写入）或很小（被覆盖）
- **无法播放**：播放器无法解析文件结构
- **数据丢失**：部分数据被覆盖或丢失
- **时间戳错误**：音视频不同步

## 四、解决方案

### 4.1 TCP模式改进方案

**方案1：添加进程ID到文件名**
```cpp
// 修改 CCVideoClient.cpp
char filename[256];
pid_t pid = getpid();
snprintf(filename, sizeof(filename), "./record_tcp_%d_%ld.mp4", 
         pid, time(nullptr));
CCVideoWriter::GetInstance()->StartVideoWriterWithPath(filename);
```

**方案2：添加时间戳到文件名**
```cpp
char filename[256];
time_t now = time(nullptr);
struct tm* t = localtime(&now);
snprintf(filename, sizeof(filename), "./record_tcp_%04d%02d%02d_%02d%02d%02d.mp4",
         t->tm_year + 1900, t->tm_mon + 1, t->tm_mday,
         t->tm_hour, t->tm_min, t->tm_sec);
```

**方案3：命令行参数指定文件名**
```cpp
// 修改 main.cpp，支持文件名参数
if (argc >= 5) {
    filename = argv[4];  // 用户指定文件名
} else {
    // 使用默认文件名
}
```

### 4.2 RTMP模式改进方案

**方案1：添加毫秒级时间戳**
```cpp
// 修改 main.cpp
struct timespec ts;
clock_gettime(CLOCK_REALTIME, &ts);
snprintf(filename, sizeof(filename), 
         "record_%04d%02d%02d_%02d%02d%02d_%03ld.mp4",
         t->tm_year + 1900, t->tm_mon + 1, t->tm_mday,
         t->tm_hour, t->tm_min, t->tm_sec,
         ts.tv_nsec / 1000000);  // 毫秒
```

**方案2：添加进程ID**
```cpp
pid_t pid = getpid();
snprintf(filename, sizeof(filename), 
         "record_%04d%02d%02d_%02d%02d%02d_%d.mp4",
         t->tm_year + 1900, t->tm_mon + 1, t->tm_mday,
         t->tm_hour, t->tm_min, t->tm_sec, pid);
```

**方案3：添加随机数**
```cpp
int random = rand() % 10000;
snprintf(filename, sizeof(filename), 
         "record_%04d%02d%02d_%02d%02d%02d_%04d.mp4",
         t->tm_year + 1900, t->tm_mon + 1, t->tm_mday,
         t->tm_hour, t->tm_min, t->tm_sec, random);
```

### 4.3 最佳实践

**推荐方案：时间戳 + 进程ID**
```cpp
char filename[256];
time_t now = time(nullptr);
struct tm* t = localtime(&now);
pid_t pid = getpid();

snprintf(filename, sizeof(filename), 
         "record_%04d%02d%02d_%02d%02d%02d_%d.mp4",
         t->tm_year + 1900, t->tm_mon + 1, t->tm_mday,
         t->tm_hour, t->tm_min, t->tm_sec, pid);
```

**优点：**
- 文件名唯一（时间戳 + 进程ID）
- 便于识别（包含时间信息）
- 避免冲突（即使同一秒启动）

## 五、总结

### 5.1 文件冲突情况

| 场景 | TCP模式 | RTMP模式 | 是否冲突 |
|------|---------|----------|---------|
| 多个TCP客户端 | `./20211115.mp4` | - | ❌ **冲突** |
| 多个RTMP客户端（不同时间） | - | 不同文件名 | ✅ **不冲突** |
| 多个RTMP客户端（同一秒） | - | 相同文件名 | ❌ **冲突** |
| TCP + RTMP | `./20211115.mp4` | `record_*.mp4` | ✅ **不冲突** |

### 5.2 关键要点

1. **单例模式只在进程内有效**：多进程 = 多个独立实例
2. **TCP模式有冲突风险**：硬编码文件名，多个实例会冲突
3. **RTMP模式部分安全**：动态文件名，但同一秒启动会冲突
4. **文件冲突会导致损坏**：多个进程写入同一文件会损坏文件结构

### 5.3 建议

1. **修改TCP模式**：添加时间戳或进程ID到文件名
2. **改进RTMP模式**：添加毫秒级时间戳或进程ID
3. **支持命令行参数**：允许用户指定输出文件名
4. **添加文件锁**：使用文件锁防止多进程写入（可选）
